# 可変プロンプトフォーム 要件定義書

作成日：2026-10-10
更新日：2026-10-12（プレイグラウンドの追加、利用者を公開に変更）

## 1. 概要

可変部分を含むプロンプトをテンプレートとして登録し、可変部分から入力フォームを自動で作り、入力した値を差し込んだプロンプトをコピーできる、ブラウザ完結型のウェブツールを作る。

### 1.1 目的

- 毎回少しだけ値を変えて使うプロンプト（例：日付とアカウントだけが変わる日記プロンプト）を、手で書き換えずに素早く用意する
- 書き換えの漏れや、固定部分の誤った編集を防ぐ
- 初めて開いた人が、手持ちのプロンプトを貼るだけで「入力欄ができて、入力するとプロンプトが完成する」ことをすぐ体感できるようにする

### 1.2 利用者

- GitHub Pagesで公開し、URLを開いた人なら誰でも使える
- 初めての利用者は、起動時のプレイグラウンド（3.8）で使い方を体感してから、テンプレートを登録して使う
- データは各利用者のブラウザ内にだけ保存する。ログイン、アカウント管理、利用者どうしの共有は行わない

### 1.3 スコープ

| 区分 | 内容 |
| --- | --- |
| 対象 | プレイグラウンド、テンプレートの登録・編集・切り替え、可変部分からのフォーム生成、プレビュー、コピー、コピー履歴、JSONでのバックアップ |
| 対象外 | サーバー、ログイン、複数人での共有、AIサービスとの直接連携（API呼び出し・タブを開く機能） |

## 2. 用語定義

| 用語 | 意味 |
| --- | --- |
| テンプレート | 固定部分と変数を含むプロンプト本文と、その変数設定のまとまり |
| 本文 | テンプレートのプロンプト文。変数は `{{変数名}}` と書く |
| 変数 | 本文中の `{{変数名}}`。利用画面で入力欄になる |
| 変数設定 | 変数ごとの表示名・型・初期値などの設定。本文とは別の画面で編集する |
| 未使用の変数 | 設定は残っているが、本文から `{{変数名}}` が消えた変数 |
| 生成プロンプト | 本文の変数を入力値で置き換えた、コピーするためのプロンプト |
| 編集固定モード | プレビューを直接編集したあと、フォームの変更を反映しない状態 |
| コピー履歴 | コピーした生成プロンプトの記録（直近50件） |
| プレイグラウンド | 手持ちのプロンプトを貼り付けて、その場でフォームの生成と入力を試せる画面。内容は保存しない |
| マイテンプレート | 登録したテンプレートを使う画面（従来の利用画面） |

## 3. 機能要件

機能はテンプレート管理、変数、利用、履歴、バックアップ、プレイグラウンドの6つに分ける。IDは実装やテストで参照するときに使う。

### 3.1 テンプレート管理

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-01 | 一覧表示 | 登録済みのテンプレートを名前と更新日時で一覧表示する |
| F-02 | 新規作成 | 名前と本文を入力して作成する |
| F-03 | 編集 | 名前・本文・変数設定を編集して保存する |
| F-04 | 複製 | 既存のテンプレートをコピーして新しいテンプレートを作る |
| F-05 | 削除 | 確認ダイアログを出してから削除する |
| F-06 | 切り替え | 利用画面で使うテンプレートを選ぶ |

### 3.2 変数の検出と連動

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-11 | 自動検出 | 本文中の `{{変数名}}` を検出する。本文に新しい名前が書かれたら、設定一覧に自動で追加する（初期の型は1行テキスト） |
| F-12 | 未使用の扱い | 本文から消えた変数は設定を残し、「未使用」と表示する。削除は手動で行う |
| F-13 | 同名の集約 | 同じ名前が本文に何回出ても入力欄は1つにまとめ、すべての箇所に同じ値を差し込む |
| F-14 | 変数名のルール | 使える文字は日本語・英数字・アンダースコア。記号やスペースを含む `{{…}}` は変数として扱わず、編集画面で警告する |
| F-15 | エスケープ | `\{{` と書いた箇所は変数ではなく、文字の `{{` として出力する |

### 3.3 入力欄の型

| 型 | 入力UI | 型ごとの設定 | 差し込まれる値 |
| --- | --- | --- | --- |
| 1行テキスト | テキストボックス | なし | 入力した文字列 |
| 複数行テキスト | テキストエリア | なし | 入力した文字列（改行を含む） |
| 日付 | 日付ピッカー | 出力形式（例：`YYYY年MM月DD日`） | 出力形式で整形した文字列 |
| 選択肢 | ドロップダウン | 候補の一覧 | 選んだ候補 |
| 数値 | 数値入力 | 最小値と最大値 | 入力した数値 |
| チェックボックス | チェックボックス | ONのときの文、OFFのときの文（空欄も可） | ON/OFFに対応する文 |

### 3.4 変数ごとの共通設定

| 設定項目 | 内容 |
| --- | --- |
| 表示名 | フォームに表示するラベル。未設定のときは変数名を表示する |
| 必須 | ONの場合、未入力のときはコピーできない |
| 初期値 | 入力欄の初期値 |
| プレースホルダー・説明文 | 入力欄に薄く表示する例と、欄の下に表示する説明 |
| 日付の特殊な初期値 | 日付型のみ。「今日」または「昨日」を初期値にできる |
| 前回値の引き継ぎ | ONの場合、前回コピーしたときの値を初期値にする。初期値より優先する |
| 並び順 | フォーム上の表示順。ドラッグなどで並べ替える |

### 3.5 利用画面（入力・プレビュー・コピー）

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-31 | フォーム生成 | 変数設定から入力フォームを作る。未使用の変数は表示しない |
| F-32 | リアルタイムプレビュー | 入力するたびに生成プロンプトを更新する |
| F-33 | 未入力の強調 | 未入力の変数をプレビュー上で `{{変数名}}` のまま色付きで表示する |
| F-34 | 文字数表示 | 生成プロンプトの文字数を表示する |
| F-35 | プレビューの直接編集 | プレビューをその場で手直しできる。テンプレートは変わらない |
| F-36 | 編集固定モード | プレビューを編集すると「編集中」と表示し、フォームの変更を反映しない。「リセット」で自動反映に戻す（手直しした内容は破棄する） |
| F-37 | コピー | ボタン1つで生成プロンプトをクリップボードにコピーし、「コピーしました」と表示する。必須項目が未入力のときはボタンを無効にし、未入力の項目を示す |

### 3.6 コピー履歴

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-41 | 記録 | コピーするたびに、日時・テンプレート名・生成プロンプト・入力値を記録する |
| F-42 | 件数 | 全テンプレート合計で直近50件を残し、古いものから削除する |
| F-43 | 一覧と再コピー | 一覧から選んで再コピーできる。冒頭の数行を表示して見分けやすくする |
| F-44 | 入力値の復元 | 履歴の入力値をフォームに読み込み、一部だけ変えて使える（例：日付だけ変える） |
| F-45 | 削除 | 履歴を1件ずつ、または全件削除できる |

### 3.7 バックアップ

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-51 | 全体の書き出し | 全テンプレートとコピー履歴を1つのJSONファイルに書き出す |
| F-52 | 全体の読み込み | 読み込むときは「追加」か「全置換」を選ぶ。全置換の前には確認ダイアログを出す |
| F-53 | テンプレート単位の書き出し | 1つのテンプレートを1つのJSONファイルに書き出す。履歴は含めない |
| F-54 | テンプレート単位の読み込み | 1つのテンプレートを追加する。同じ名前のテンプレートがある場合は名前に「(2)」などを付ける |
| F-55 | 形式チェック | 形式やバージョンが合わないファイルはエラーを表示し、データを変更しない |

### 3.8 プレイグラウンド

初めての利用者が、テンプレートを登録する前に仕組みを体感するための画面。起動時に毎回表示する。

| ID | 機能 | 内容 |
| --- | --- | --- |
| F-61 | 貼り付け欄 | `{{変数名}}` を含むプロンプトを貼り付ける（直接入力も可）。開いた時点ではサンプル（7.4）が入っている |
| F-62 | リアルタイム生成 | 貼り付け欄を変更するたびに変数を検出し、入力フォームを作り直す。検出ルールは F-11・F-13〜F-15 と同じ。本文から消えた変数は残さない（未使用の扱いはしない） |
| F-63 | 型の切り替え | 各入力欄の横で型（3.3の6種類）を選べる。新しく検出した変数は1行テキスト。選択肢は候補、チェックボックスはONのときの文をその場で入力できる。日付は初期値「今日」、出力形式は既定値 |
| F-64 | リアルタイムプレビュー | 入力するたびに生成プロンプトを更新する。未入力の変数は F-33 と同じく色付きで表示し、文字数を表示する。プレビューの直接編集（F-35）はしない |
| F-65 | コピー | 生成プロンプトをコピーできる（Ctrl/⌘ + Enter も可）。必須の概念はなく、未入力の箇所は `{{変数名}}` のままコピーし、その旨を案内する。コピー履歴には記録しない |
| F-66 | テンプレートとして保存 | 本文と変数の型・設定を引き継いで編集画面を開く。名前を付けて保存すると、マイテンプレートに追加される。入力した値は初期値にしない |
| F-67 | サンプルに戻す・クリア | 貼り付け欄をサンプルに戻す、または空にする |
| F-68 | 保存しない | プレイグラウンドの内容はlocalStorageに保存しない。ページを開き直すとサンプルに戻る |

## 4. 画面要件

画面はプレイグラウンド、利用画面（マイテンプレート）、編集画面の3つに分ける。プレイグラウンドと利用画面は、画面上部のタブ「プレイグラウンド｜マイテンプレート」で切り替える。一覧・履歴・バックアップはドロワーやダイアログで開く。UIは日本語のみとする。

### 4.1 画面一覧

| 画面 | 主な要素 | 移動先 |
| --- | --- | --- |
| プレイグラウンド（起動時） | 説明文、貼り付け欄、入力フォーム（型の切り替え付き）、プレビュー、文字数、コピー、テンプレートとして保存 | 利用画面、編集画面、テンプレート一覧、コピー履歴、設定 |
| 利用画面（マイテンプレート） | テンプレート選択、入力フォーム、プレビュー、文字数、コピーボタン、リセットボタン | 編集画面、テンプレート一覧、コピー履歴、設定 |
| 編集画面 | テンプレート名、本文エディタ、変数設定の一覧（未使用の表示を含む）、保存・キャンセル | 利用画面（保存時）、開く前の画面（キャンセル時） |
| テンプレート一覧（ドロワー） | 一覧、新規作成、複製、削除、単位の書き出し・読み込み | 利用画面（テンプレートを選んだとき）、編集画面 |
| コピー履歴（ドロワー） | 履歴一覧、再コピー、入力値の復元、削除 | 利用画面 |
| 設定（ダイアログ） | テーマ切り替え、全体の書き出し・読み込み | 利用画面 |

### 4.2 レイアウト

- **PC（目安：幅768px以上）**：利用画面は左にフォーム、右にプレビューを並べる2列。編集画面は左に本文、右に変数設定を並べる
- **PC・プレイグラウンド**：幅1024px以上では左から「貼り付け → 入力 → プレビュー」の横3列。768〜1023pxでは貼り付け欄を上段に置き、下段を入力とプレビューの2列にする
- **スマートフォン**：縦1列。利用画面は「入力」と「プレビュー」をタブで切り替え、プレイグラウンドは「貼り付け」「入力」「プレビュー」をタブで切り替える。コピーボタンは画面下部に常に表示する

### 4.3 起動時の動き

- 毎回プレイグラウンドを表示する（テンプレートの有無に関係なく、サンプル入りで開く）
- マイテンプレートのタブでは、前回最後に使ったテンプレートを開く
- テンプレートが1つもない状態でマイテンプレートを開いた場合は、テンプレートの新規作成を案内する

### 4.4 テーマ

- OSのライト/ダーク設定に合わせて自動で切り替える
- 設定から手動で「ライト／ダーク／自動」を選べ、その選択を保存する

## 5. データ要件

データはすべてブラウザのlocalStorageに保存し、外部には送信しない。書き出しファイルには形式バージョンを持たせ、将来の形式変更に備える。

### 5.1 保存キー

| キー | 内容 |
| --- | --- |
| `pf.templates` | テンプレートの配列 |
| `pf.history` | コピー履歴の配列（直近50件） |
| `pf.lastValues` | テンプレートIDごとの前回入力値 |
| `pf.settings` | テーマ、最後に使ったテンプレートID |

### 5.2 テンプレート

```json
{
  "id": "uuid",
  "name": "X日記",
  "body": "…- アカウント: {{アカウント}}\n- 日付: {{日付}}…",
  "variables": [
    {
      "name": "アカウント",
      "label": "Xアカウント",
      "type": "text",
      "required": true,
      "default": "",
      "placeholder": "@なしで入力",
      "help": "",
      "keepLast": true,
      "order": 1,
      "unused": false,
      "options": {}
    },
    {
      "name": "日付",
      "label": "日付",
      "type": "date",
      "required": true,
      "default": "yesterday",
      "order": 2,
      "options": { "format": "YYYY年MM月DD日" }
    }
  ],
  "createdAt": "ISO 8601",
  "updatedAt": "ISO 8601"
}
```

型ごとの `options` は次のとおり。

| 型（`type`） | `options` |
| --- | --- |
| `text`, `textarea` | なし |
| `date` | `format`（出力形式）。`default` に `today` / `yesterday` / 固定日付を指定できる |
| `select` | `choices`（候補の配列） |
| `number` | `min`, `max` |
| `checkbox` | `onText`, `offText` |

### 5.3 コピー履歴

```json
{
  "id": "uuid",
  "templateId": "uuid",
  "templateName": "X日記",
  "values": { "アカウント": "example", "日付": "2026-10-09" },
  "output": "生成プロンプト全文",
  "edited": false,
  "copiedAt": "ISO 8601"
}
```

- `edited` は、編集固定モードで手直ししてからコピーしたかどうかを表す
- テンプレート名は記録時点の名前を残し、テンプレートを削除しても履歴は残す

### 5.4 書き出しファイル

| 種類 | ファイル名の例 | 中身 |
| --- | --- | --- |
| 全体 | `prompt-form-backup-20261010.json` | `{ "format": "prompt-form", "version": 1, "kind": "backup", "templates": [...], "history": [...] }` |
| テンプレート単位 | `template-X日記.json` | `{ "format": "prompt-form", "version": 1, "kind": "template", "template": {...} }` |

- 読み込み時はテンプレートIDを振り直し、既存のデータと衝突しないようにする

## 6. 非機能要件

| 区分 | 要件 |
| --- | --- |
| 提供形態 | 素のHTML・CSS・JavaScriptで作る静的サイト。ビルド工程は設けない。GitHub Pagesで公開する |
| 外部依存 | 原則として使わない。使う場合はCDNから読み込み、オフラインでも基本機能が動くようにする |
| 対応ブラウザ | PCとスマートフォンの最新のChrome・Safari・Edge・Firefox |
| 性能 | 本文1万字・変数30個程度で、入力からプレビュー更新までの遅延を感じない（目安：100ms以内） |
| 保存容量 | localStorageの上限（目安：5MB）に近づいたら警告を出し、書き出しを促す |
| セキュリティ | 入力値や本文はHTMLとして解釈せず、テキストとして表示する（XSS対策）。データは外部に送信しない |
| 公開範囲 | GitHub Pagesで公開するのはツール本体のみ。誰でも開いて使えるが、テンプレートと履歴は各利用者のブラウザ内にだけ保存され、他の利用者や開発者からは見えない |
| クリップボード | Clipboard APIを使う。使えない環境では選択状態にして手動コピーを案内する |
| 保存の単位 | localStorageはURL（オリジン）ごとに分かれるため、ローカルで開いたファイルとGitHub Pages版ではデータを共有しない。移行は書き出し・読み込みで行う |

## 7. 具体例：X日記テンプレート

X日記プロンプトは、固定部分はそのままにし、可変部分を次のように変数化して登録する。最低限変数にするのは「アカウント」と「日付」で、残りは初期値付きの変数にしておくと、あとから変えられる。

### 7.1 本文の可変部分

```markdown
# 可変部分

- アカウント: {{アカウント}}
- 日付: {{日付}}（JST）
- 日記の長さ: {{日記の長さ}}
- 優先: {{優先}}
- 追加ルール: {{追加ルール}}
- 出力: {{出力}}
```

### 7.2 変数設定

| 変数 | 型 | 必須 | 初期値・設定 | 前回値の引き継ぎ |
| --- | --- | --- | --- | --- |
| アカウント | 1行テキスト | ○ | プレースホルダー「@なしで入力」 | ON |
| 日付 | 日付 | ○ | 初期値「昨日」、出力形式 `YYYY年MM月DD日` | OFF |
| 日記の長さ | 選択肢 | ○ | 候補「1〜3行／1〜5行」、初期値「1〜5行」 | OFF |
| 優先 | 複数行テキスト | − | 初期値「あとで見返せること（曲名・イベント名・手元の物と画面の対応・自分の判定）」 | OFF |
| 追加ルール | 複数行テキスト | − | 初期値「数値と事実には取得日と出典を併記し、古い可能性があれば明記する」 | OFF |
| 出力 | 選択肢 | ○ | 候補「分析（時系列の束ね）＋見返し用日記／分析のみ」、初期値は前者 | OFF |

### 7.3 利用の流れ

1. ツールを開くと、前回使ったX日記テンプレートが表示される
2. アカウントには前回の値が、日付には昨日の日付が入っている
3. 日付だけ確認・変更し、プレビューで内容を確かめる
4. コピーボタンを押し、AIサービスに貼り付ける

固定部分の「1日1〜5行」は「日記の長さ」と内容が重なる。長さを変数にするなら、固定部分の該当箇所も `{{日記の長さ}}` に置き換えると、両者が食い違わない。

### 7.4 プレイグラウンドのサンプル

プレイグラウンドを開いたときに貼り付け欄に入っているサンプル。誰でも状況を想像しやすいメール返信の依頼にし、型の違いと同名の集約（F-13）が見えるようにする。

```markdown
あなたはメールの返信を手伝うアシスタントです。
次の条件で、{{相手}}さんへの返信メールの下書きを書いてください。

## 受け取ったメール
{{受け取ったメール}}

## 伝えたいこと
{{伝えたいこと}}

## 条件
- 口調: {{口調}}
- 長さ: {{文字数}}字程度
- 返信日: {{返信日}}
- 冒頭は「{{相手}}さん」で始め、最後に署名「{{自分の名前}}」を入れる
```

| 変数 | 型 | 初期値・設定 |
| --- | --- | --- |
